# 城乡结对支教平台后端架构设计文档

## 1. 项目概述
### 1.1 项目背景
本项目旨在打造一个"线上线下融合"的智慧云支教微信小程序平台。通过客观数据的智能双向互选算法，高效连接城市志愿者与乡村孩子；并在平台内部直接提供受监督的即时通讯与音视频会议模块，建立持久的"手拉手"陪伴。最终通过低成本、可持续的方式突破时空限制，并配合每年线下的深度研学营，实现长效教育帮扶。

### 1.2 核心功能
- 多角色用户体系：一级管理员、二级管理员（乡村老师）、教师端（城市志愿者）、学员端（乡村学生）
- 智能匹配与双向互选：基于算法的志愿者推荐系统
- 即时通讯与视频会议：内置聊天功能 + 外部腾讯会议集成
- 消息通知系统：微信订阅消息实时提醒
- 数据统计与分析：管理员可视化数据看板

### 2.3 分层架构设计
```
表现层 (Presentation Layer)
├── Controller: 接收请求，参数校验，返回响应
├── DTO: 数据传输对象
└── VO: 视图对象

业务层 (Business Layer)
├── Service: 业务逻辑实现
├── Manager: 复杂业务协调
└── Event: 领域事件处理

数据访问层 (Data Access Layer)
├── Mapper: 数据库操作接口
├── Entity: 实体类
└── Repository: 数据访问抽象

基础设施层 (Infrastructure Layer)
├── Config: 配置管理
├── Util: 工具类
├── Cache: 缓存实现
└── External: 外部服务集成
```

## 3. 数据库设计
### 3.1 核心表关系
```
用户表 (user) ──┬── 管理员信息表 (admin_profile)
                ├── 志愿者信息表 (teacher_profile)
                └── 学生信息表 (student_profile)
                    │
                    └── 匹配结对表 (match_pair) ──┬── 聊天消息表 (chat_message)
                                                 └── 会议表 (meeting)
```

### 3.2 关键特性
1. **数据隔离**：通过`school_id`、`region_code`实现二级管理员数据隔离
2. **软删除**：所有表支持软删除，保留历史数据
3. **JSON字段**：使用MySQL JSON类型存储灵活数据结构（空闲时间、科目等）
4. **索引优化**：针对查询频率高的字段建立复合索引

## 4. 安全设计

### 4.1 认证机制
- **微信登录**：小程序获取code，后端调用微信API换取openid
- **JWT令牌**：登录成功后生成JWT，包含用户ID、角色等信息
- **Token刷新**：支持refresh token机制，延长会话有效期

### 4.2 权限控制
- **角色权限**：基于RBAC模型，四类角色各有不同权限
- **数据权限**：二级管理员只能访问其管辖区域的数据
- **方法级权限**：使用`@PreAuthorize`注解控制方法访问
- **API级权限**：通过拦截器校验接口访问权限

### 4.3 数据安全
- **密码加密**：BCrypt算法加密存储
- **敏感信息脱敏**：返回前端的数据进行脱敏处理
- **SQL防注入**：MyBatis-Plus参数化查询
- **XSS防护**：输入输出过滤

## 5. 核心模块设计

### 5.1 用户管理模块
- **多角色用户体系**：统一用户表+角色扩展表设计
- **审核机制**：志愿者需要管理员审核才能激活
- **代管模式**：二级管理员可代管学生账号

### 5.2 智能匹配模块
```
匹配算法流程：
1. 数据准备：收集学生需求、志愿者能力、时间匹配度
2. 权重计算：根据算法配置计算各项权重分
   - 科目匹配度（40%）
   - 时间匹配度（30%）
   - 紧急程度（20%）
   - 性格匹配（10%）
3. 推荐排序：综合得分排序，返回Top N推荐
4. 双向选择：学生发起申请，志愿者确认
```

### 5.3 消息通知模块
- **微信订阅消息**：关键业务节点触发微信服务通知
- **站内消息**：系统消息存储，支持已读未读状态
- **异步处理**：使用事件驱动模式，异步发送消息

### 5.4 聊天模块
- **实时通信**：WebSocket实现实时消息推送
- **消息存储**：所有聊天记录持久化存储
- **离线消息**：支持离线消息拉取

### 5.5 志愿时长与纪要管理模块（新增）
- **工作流引擎**：实现严格的状态单向流转：`Draft -> 待学生确认-> 待管理员审核-> 审核通过/ 审核拒绝`。
- **并发防刷**：管理员在执行审核通过操作累加时长时，使用数据库事务（`@Transactional`）并配合乐观锁，防止因多次点击导致的时长重复累加。
- **自动化消息联动**：
  - 教师提交后 -> 触发微信消息提醒代管老师或学生确认。
  - 学生确认后 -> 触发通知提醒二级管理员审核。
  - 管理员审核完毕 -> 通知发送给相关教师。

## 6. 性能与可扩展性

### 6.1 性能优化
- **数据库读写分离**：主库写，从库读
- **Redis缓存**：热点数据缓存（用户信息、配置等）
- **连接池**：Druid连接池管理数据库连接
- **分页查询**：所有列表接口支持分页

### 6.2 可扩展性
- **微服务化准备**：模块化设计，便于拆分为微服务
- **配置中心**：支持动态配置更新
- **服务发现**：预留服务注册发现接口

### 6.3 高可用
- **集群部署**：应用无状态，支持水平扩展
- **故障转移**：数据库主从切换，Redis哨兵模式
- **负载均衡**：Nginx负载均衡，健康检查
